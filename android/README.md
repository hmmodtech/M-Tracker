# M-TRACKER — تطبيق الأندرويد 📱

تطبيق يعرض لوحة M-TRACKER كاملة داخل التطبيق، وبيبعتلك **إشعار فوري** لكل خبر جديد،
وإذا كان الجهاز **مقفول** بتولّع الشاشة وبيظهر الخبر على شاشة القفل فوراً.

---

## 1) كيف بتوصل الإشعارات؟

```
قنوات تيليجرام/المواقع ──► السيرفر (كل 30 ثانية يجمع الأخبار)
                                  │
                                  ├─ /api/stream  ← التطبيق حافظ اتصال مفتوح (long-poll)
                                  │        يصحى بأقل من ثانية لما يوصل خبر جديد
                                  ▼
                            إشعار + شاشة كاملة على الجهاز
```

مش محتاجين Firebase ولا Play Services: التطبيق بيحافظ على اتصال واحد مع `GET /api/stream`،
والسيرفر بيخلي الطلب معلّق (حتى 120 ثانية) ويرجّعه فوراً لما يوصل خبر جديد.
هذا معناه:

- **بدون تأخير تقريباً** (عادة أقل من ثانيتين من لحظة وصول الخبر للسيرفر).
- بيشتغل حتى لو الجهاز مسكّر التطبيق (خدمة أمامية + استثناء بطارية + منبّه حراسة كل 15 دقيقة).
- الأخبار المكرّرة (نفس الخبر من 5 قنوات) بتتدمج وإشعار واحد بس بيوصل.

### شو بيصير لما تكون الشاشة مقفلة؟

| الحالة | النتيجة |
|---|---|
| صلاحية «الظهور فوق التطبيقات» ممنوحة | التطبيق بيفتح شاشة الخبر بنفسه (أضمن طريقة) |
| غير ممنوحة + أندرويد 13 وأقل | إشعار `fullScreenIntent` بيولّع الشاشة ويظهر الخبر |
| غير ممنوحة + أندرويد 14+ | إشعار عالي الأهمية بيضوي الشاشة؛ لازم تمنح «الشاشة الكاملة» من الإعدادات |

عشان هيك الإعدادات فيها زر لكل صلاحية.

## 2) التركيب على الموبايل

1. نزّل الـAPK من:
   - صفحة `/app` على السيرفر مباشرة، أو
   - الملف داخل المستودع: `static/app/m-tracker-1.0.0.apk`
2. افتح الملف → إذا طلب تسمح بـ«تثبيت من مصادر غير معروفة» اسمح لها.
3. افتح التطبيق واعمل دخول بنفس حساب الموقع (الجلسة بتنحفظ).
4. اضغط ⚙ فوق → فعّل الأربعة:
   - **الإشعارات**
   - **الظهور فوق التطبيقات** ← أهم واحدة
   - **استثناء من توفير البطارية**
   - **الشاشة الكاملة** (أندرويد 14+)
5. اضغط **«تجربة إشعار + شاشة كاملة»** → لازم تشوف شاشة الخبر بنفسك.

> أجهزة شاومي/هواوي/أوبو/فيفو: من إعدادات النظام فعّل **Autostart / تشغيل تلقائي**
> وخلّي البطارية **Unrestricted / بدون قيود** لتطبيق M-TRACKER.

## 4) البناء (كيف تطلع APK جديد)

### الطريقة السريعة — بدون Android Studio

```bash
cd android
ANDROID_SDK=/path/to/android-sdk JAVA_HOME=/path/to/jdk17 ./build_apk.sh
# الناتج: android/out/m-tracker-1.0.0.apk
```

الاسكربت بيعمل كل شي بالترتيب: `aapt2 compile/link` → `javac` → `d8` → `zipalign` → `apksigner`.
التطبيق **بدون أي مكتبات خارجية** (لا AndroidX ولا Firebase)، فما بيحتاج تنزيل أي dependency.

### الطريقة العادية — Android Studio

افتح مجلد `android/` بمشروع Gradle (ملفات `settings.gradle`/`build.gradle` جاهزة)،
أو نفّذ `./gradlew assembleRelease`. إذا بتحب Gradle يوقّع بنفس المفتاح،
خلي ملف `android/keystore/keystore.properties` موجود (بنفس الصيغة اللي بالأسفل).

### مفتاح التوقيع

أول بناء بينشئ المفتاح بمكان **خارج المستودع**:

```
~/mtracker-signing/m-tracker-release.jks
~/mtracker-signing/keystore.properties      (فيه كلمة السر)
```

(بتقدر تغيّر المكان بـ`KEYSTORE_DIR=/path ./build_apk.sh`.)

> ⚠️ **احتفظ بهذي الملفات**: بدونها ما بتقدر تنزّل إصدار محدّث فوق نسخة مركّبة بحيث
> النظام يقبله (بتضطر تحذف التطبيق وتركبه من جديد). خذ نسخة احتياطية منها.

بصمة المفتاح الحالي (SHA-256):

```
03:28:0B:B2:94:AC:70:97:08:B8:37:A9:6B:F8:F2:07:1C:C7:7E:F1:21:C3:E2:B5:40:9D:05:C6:88:F5:3E:06
```

> ⚠️ نسخة 1.0.1 موقّعة بمفتاح جديد (المفتاح الأول ضاع)، فإذا كانت نسخة قديمة مركّبة على الجهاز
> لازم **تحذف التطبيق القديم** أولاً وبعدها تركّب الجديدة.

## 6) تعديلات السيرفر اللي بيعتمد عليها التطبيق

| الملف | شو انضاف |
|---|---|
| `app.py` | `GET /api/stream` — long-poll: `since`, `scope=critical\|all`, `wait`, `baseline`, `dedup=0` |
| `app.py` | صفحة `/app` (تحميل التطبيق) |
| `database.py` | `get_messages_after`, `get_latest_message_id`, دوال كشف التكرار (`tokenize_for_dedup`, `jaccard`, `group_similar_messages`, `notified_stories`) ودوال توكنات الأجهزة |
| `gunicorn.conf.py` | عامل `gthread` + 24 خيط — ضروري حتى ما يوقف الطلب المعلّق الموقع |
| `Procfile` / `render.yaml` | التشغيل عبر `gunicorn app:app -c gunicorn.conf.py` |

> 📌 لازم تعمل Deploy للسيرفر (دمج الفرع مع `main` على Render) حتى تشتغل الإشعارات،
> لأن `/api/stream` ما كان موجود قبل.

اختبار سريع للسيرفر من أي جهاز:

```bash
curl "https://<your-server>/api/stream?baseline=1"
# {"events": [], "cursor": 1234, ...}

curl "https://<your-server>/api/stream?since=1234&wait=25&scope=critical" | head -c 400
```

## 7) سجل الإصدارات

### 1.0.1 — إصلاح كراش أندرويد 14+
كان التطبيق يفتح ويسكّر فوراً على أندرويد 14 وأحدث، والسبب:
`registerReceiver()` صار من أندرويد 14 **يفرض** تمرير `RECEIVER_EXPORTED`/`RECEIVER_NOT_EXPORTED`
لما تكون الرسائل خاصة بالتطبيق، وإلا بيرمي `SecurityException` ويقتل التطبيق.
صار التمرير صحيح (`RECEIVER_NOT_EXPORTED`) + كل شي بالواجهة صار داخل حماية `try/catch`
حتى ما يموت التطبيق صامت.

انضاف كمان:
- **سجل أخطاء داخل التطبيق**: أي خطأ بينكتب بـ`files/crash.log`، وبيطلع تلقائياً بالفتحة الجاية
  مع زر «مشاركة / نسخ» حتى تبعته للمسؤول. موجود كمان بـ**الإعدادات ← التشخيص ← آخر خطأ**.
- **تشخيص واضح بالحالة**: «السيرفر بحاجة تحديث» إذا السيرفر ما فيه `/api/stream`،
  أو «النظام منع تشغيل المتابعة بالخلفية» مع شرح كيف تتحل.
- **زر «تشغيل المتابعة الآن»** بالإعدادات يعيد ضبط المؤشر ويشغّل الخدمة من جديد.
- بيطلب صلاحية الإشعارات أول ما يفتح (بدونها ما بيبين أي شي).

## 8) مشاكل شائعة

| المشكلة | الحل |
|---|---|
| الإشعارات ما توصل | تأكد إنه «خدمة المتابعة» مفعّلة، والشارة فوق بالبرنامج مكتوب «متصل». جرّب «تجربة إشعار» |
| بيوصل إشعار بس الشاشة ما تولّع | منح «الظهور فوق التطبيقات» + «الشاشة الكاملة» (أندرويد 14+) + استثناء البطارية |
| بيوصل متأخر 1–2 دقيقة | تأكد إنه «توفير البطارية» مقفول، وإنه الجهاز مش بوضع Doze قوي |
| التطبيق يفتح ويسكّر فوراً | كان هذا كراش أندرويد 14 — تحدّث لـ1.0.1. وإذا ضل، افتح الإعدادات ← التشخيص ← «آخر خطأ» وابعت النص |
| مكتوب «السيرفر بحاجة تحديث» | لسا ما اننشر التحديث على السيرفر (لازم merge للفرع + Deploy على Render) |
| «App not installed» وقت التركيب | في نسخة قديمة بمفتاح توقيع مختلف — احذف التطبيق القديم أولاً |
| «توكن غلط» بالإعدادات | السيرفر عليه `STREAM_TOKEN`، اكتب نفس القيمة بالتطبيق أو شيلها من السيرفر |
| أول فتح بطيء (~50 ثانية) | خطة Render المجانية بتنيم السيرفر. الاتصال مفتوح 24/7 فبيضل صاحي، بس أول طلب بعد التوقف بيبطأ |
| الخدمة تتوقف بعد سحب التطبيق من «الأخيرة» | فعّل Autostart على أجهزة شاومي/هواوي/أوبو، والمنبّه الاحتياطي بيعيد تشغيلها خلال ربع ساعة |

### قيود لازم تعرفها

- إذا المستخدم عمل **Force Stop** للتطبيق من إعدادات النظام، الخدمة ما بترجع تسشتغل لحتى يفتح التطبيق بنفسه.
- طريقة الشرح هذي (اتصال مفتوح) بتستهلك بطارية أكثر من FCM. إذا بدك دقة وأداء أعلى لاحقاً
  فيك تحوّل لـFirebase Cloud Messaging: السيرفر أصلاً فيه `push.py` (firebase-admin) ودالة `/api/register-device`.
- السيرفر على خطة مجانية: إذا نزل وطال وقت الإيقاظ، أول إشعار ممكن يتأخر لحظات.
